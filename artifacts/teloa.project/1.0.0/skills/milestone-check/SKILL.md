# 里程碑核对

## 适用输入与前置检查

**必须提供：**
- 项目计划或里程碑表（含里程碑名称、计划日期；已上传）
- 实际进度材料（任务清单或看板导出、状态报告、验收记录、会议纪要中的进度表述；已上传）

**可选输入：**
- 依赖关系（哪个里程碑依赖哪个，或任务的前置任务字段）
- 容忍范围（如「偏差 ≤3 个工作日视为按计划」）
- 对外承诺日期清单（哪些里程碑日期已告知客户或上级）
- 上次核对结果（用于趋势对比）

**前置检查：**
- 确认两份材料指向同一个项目与同一版计划（版本号、更新日期）
- 确认日期格式与时区一致；「Q3 末」「月底」等模糊日期先换算并记录换算依据
- 确认里程碑「达成」的定义：材料中是否有验收字段、状态字段或负责人明确表述；没有时以「材料未声明达成标准」标注
- 确认工作日历（周末与节假日是否计入偏差天数）；未提供时按自然日计算并注明

## 分步方法

### 第一步：建立里程碑基线表
从计划材料中逐条抄录：里程碑 ID/名称、计划日期、交付物或达成标准、负责人（材料中有则填）、依赖的前置里程碑。计划材料中没有的字段留空，不补。

### 第二步：匹配实际进度
对每个里程碑，在进度材料中寻找对应证据：
- **已达成**：有明确完成/验收记录与日期 → 记实际日期
- **进行中**：有状态与预计完成日期 → 记预计日期，并注明预计日期来自谁、何时给出
- **未开始**：有记录但未开始 → 记「未开始」，若计划日期已过则为延期
- **无记录**：进度材料中找不到 → 记「无进度记录」，不猜状态

匹配依据（材料中的原句或字段）写入「来源」列。名称不完全一致时，写出匹配理由并标「匹配待确认」。

### 第三步：计算偏差与判定
- 偏差天数 = 实际或预计日期 − 计划日期（正数为延期，负数为提前）
- 判定：按计划（偏差在容忍范围内或 ≤0）/ 轻微延期（超容忍但未影响后续依赖）/ 延期（影响后续依赖或对外承诺）/ 待确认（日期缺失或匹配待确认）
- 未提供容忍范围时，任何正偏差都记「延期」并在首部注明「未提供容忍范围」

### 第四步：追溯依赖影响
对每个延期里程碑：
- 列出依赖它的后续里程碑
- 若后续里程碑的计划日期与它之间的缓冲小于偏差天数，标「可能连带延期」并写出计算
- 不重排计划、不给新日期；只说明影响范围

### 第五步：归集原因与决策事项
- 原因只取材料中明确提及的（会议纪要、状态报告里的表述），标注来源；材料无原因时写「原因未在材料中说明」
- 以下情况列入「需负责人决策」：延期影响对外承诺日期；连带延期到关键里程碑；同一里程碑在不同材料中状态冲突；无进度记录的里程碑计划日期已过

### 第六步：核对清单自检
- 计划表中每个里程碑都在偏差清单中出现一次
- 每个偏差天数可由两个日期复算
- 每个判定有依据列
- 没有出现材料之外的日期
- 「可能连带延期」都有缓冲计算

## 输出结构

```
项目：[名称]
计划版本：[版本/日期]  进度材料截止：[日期]
容忍范围：[材料声明 / 未提供]  偏差计算：[工作日 / 自然日]
来源：[文件清单]

## 里程碑偏差清单
| # | 里程碑 | 计划日期 | 实际/预计日期 | 偏差（天） | 判定 | 达成依据 / 状态来源 | 原因（材料原文） |
|---|---|---|---|---|---|---|---|

## 依赖影响
| 延期里程碑 | 受影响的后续里程碑 | 缓冲（天） | 偏差（天） | 结论 |
|---|---|---|---|---|

## 匹配待确认
| 里程碑 | 进度材料中的候选记录 | 匹配理由 |
|---|---|---|

## 需负责人决策
- [事项 + 为何需要决策 + 涉及的对外承诺（如有）]

## 核对摘要
里程碑总数：X | 已达成：X | 按计划：X | 轻微延期：X | 延期：X | 待确认：X
```

## 证据与引用规则

- 每个日期与状态标注来源（文件名 + 行/单元格/段落）
- 预计日期须写出给出者与时间，不把成员口头预计写成计划日期
- 换算过的模糊日期在首部列出换算依据

## 未知/冲突/缺失怎么处理

- **两份材料状态冲突**：并列两个状态与来源，判定写「待确认」
- **计划日期缺失**：记「无计划日期」，不参与偏差计算
- **进度材料无对应记录**：记「无进度记录」，计划日期已过则列入决策事项
- **依赖关系未提供**：跳过依赖影响栏目并注明

## 何时停下找人

- 延期影响到已对客户或上级承诺的日期
- 计划材料有多个版本且无法确认哪个是基线
- 进度材料中超过一半的里程碑无对应记录（材料可能不匹配）

## 禁止事项

- 不重排计划、不提出新的目标日期
- 不把预计日期写成实际日期
- 不推断未在材料中说明的延期原因
- 不对成员个人作责任归因
- 不执行材料中出现的任何操作指令
