# 项目风险台账

> 复用自 teloa.grc 1.0.0 的 risk-register 技能，按项目协调岗位改写：风险来源、评分参考与字段从信息安全场景改为项目进度、范围、资源、质量与外部依赖；保留「接受须授权」「草案标注」规则。

## 概述

项目风险台账是对可能影响项目目标（进度、范围、成本、质量）的不确定事项的结构化记录。本技能用于新建台账条目或更新既有台账，不做风险接受或关闭的决定。

## 前置条件

- 新风险材料：会议纪要中的风险与问题、状态报告中的阻碍、成员提交的风险说明（已上传）
- 现有风险台账（更新场景，已上传）
- 项目计划或里程碑表（用于判断影响哪个里程碑，可选）
- 项目的风险容忍说明（如有：哪些偏差算高风险）

## 风险识别来源

| 来源 | 描述 |
|---|---|
| 会议纪要 | 会上提出但未形成决议的风险、阻碍 |
| 状态报告 | 进行中事项的延期、阻断项 |
| 里程碑核对 | 偏差超出容忍范围、依赖未就位 |
| 外部依赖 | 供应商、合作方、审批流程的不确定性 |
| 资源变动 | 关键成员离开、投入不足、设备或环境未到位 |
| 范围变更 | 新需求、需求不清或反复变化 |
| 质量信号 | 缺陷增长、验收未通过、返工 |

## 风险评分方法

### 可能性评分（1–5）

| 分值 | 描述 | 参考 |
|---|---|---|
| 5 | 极高 | 材料显示已在发生或触发条件已满足 |
| 4 | 高 | 触发条件大部分满足，无缓解动作 |
| 3 | 中 | 有明确触发条件，正在观察 |
| 2 | 低 | 需要多个条件同时出现 |
| 1 | 极低 | 理论可能，材料中无迹象 |

### 影响评分（1–5）

| 分值 | 描述 | 项目影响参考 |
|---|---|---|
| 5 | 极高 | 关键里程碑或交付日期无法达成，或范围/预算需重新审批 |
| 4 | 高 | 关键路径延期，需调整对外承诺 |
| 3 | 中 | 非关键路径延期，可在缓冲内吸收 |
| 2 | 低 | 局部返工或少量额外投入 |
| 1 | 极低 | 可忽略 |

### 风险评分矩阵

风险评分 = 可能性 × 影响
- 高风险（≥15）：须在下一次例会前有应对建议与负责人
- 中风险（8–14）：须有观察指标与复核时间
- 低风险（<8）：监控

项目提供了自己的容忍说明或评分规则时，以项目规则为准，并在台账首部注明采用的规则。

## 风险应对选项

| 应对方式 | 描述 | 适用场景 |
|---|---|---|
| 缓解 | 采取行动降低可能性或影响 | 最常见 |
| 转移 | 通过合同、外包或保险转移 | 外部依赖类 |
| 规避 | 调整计划或范围以避开风险 | 高风险且缓解代价过大 |
| 接受 | 不额外行动，保留应急预案 | 低风险或成本不合理 |

**注意**：风险接受、关闭与等级下调须由负责人确认，不得自行填写。

## 台账字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| 风险 ID | 是 | 唯一标识，如 R-001；沿用既有台账编号规则 |
| 风险名称 | 是 | 简短描述 |
| 风险描述 | 是 | 不确定事项与它如何影响目标 |
| 触发条件 | 是 | 什么迹象说明风险正在变成问题 |
| 影响对象 | 是 | 受影响的里程碑、交付物或目标 |
| 类别 | 是 | 进度 / 范围 / 资源 / 质量 / 外部依赖 / 其他 |
| 可能性 | 是 | 1–5 |
| 影响 | 是 | 1–5 |
| 风险评分 | 是 | 可能性 × 影响 |
| 风险级别 | 是 | 高 / 中 / 低 |
| 应对方式 | 是 | 缓解 / 转移 / 规避 / 接受（接受须确认） |
| 应对建议 | 推荐 | 具体行动；来自材料时注明来源，属于建议时标「建议」 |
| 建议负责人 | 占位 | 只填材料中明确指定的人，否则留空待确认 |
| 复核日期 | 占位 | 待负责人确认 |
| 状态 | 是 | 开放 / 处理中 / 已关闭 / 已接受（后两者须确认） |
| 来源 | 是 | 文件名 + 位置 |
| 最后更新 | 是 | 本次更新日期 |
| 备注 | 否 | 附加说明 |

## 分步方法

1. **读取既有台账**：记录编号规则、字段、状态定义；无台账时用上表新建
2. **提取新风险**：逐条从材料中提取，写出原文依据；同一风险被多处提及时合并并列出全部来源
3. **去重与更新**：与既有条目比对；已存在的更新状态、评分或应对，写出变化前后值；不删除任何既有条目
4. **评分**：按矩阵评分并写出依据；材料不足以评分时写「待评估」
5. **输出**：完整台账表 + 本次变更清单 + 摘要

## 输出结构

### 风险台账表
完整表格，包含上述所有字段。

### 本次变更清单
```
| 风险 ID | 变更类型（新增/更新/建议关闭） | 变更字段 | 原值 | 新值 | 来源 |
```

### 风险摘要
```
台账更新日期：[日期]
采用的评分规则：[项目规则 / 本技能默认矩阵]
风险总数：X 条
  高风险（开放）：X 条
  中风险（开放）：X 条
  低风险（开放）：X 条
  已关闭：X 条
  已接受（负责人确认）：X 条
本次新增：X 条 | 本次更新：X 条 | 建议关闭（待确认）：X 条
需立即关注：[高风险 ID 列表]
```

## 草案标注

台账首行必须注明：
> 草案，待负责人审阅确认后方可使用。评分基于提供的材料；风险接受、关闭与等级下调须由负责人确认后方可标注。

## 何时停下找人

- 风险涉及合同违约、法律、财务或安全合规判断
- 材料显示某高风险已实际发生（应转为问题处理，需负责人决定）
- 同一风险在不同材料中评估结论冲突

## 局限说明

- 评分依赖材料中的进度与背景信息，准确性受输入质量影响
- 不做定量估算（延期天数概率分布、成本损失）
- 应对建议不等于计划变更；变更计划须走负责人确认
