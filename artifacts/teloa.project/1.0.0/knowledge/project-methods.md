# 项目管理方法与来源索引

## 适用范围

本文档适用于项目协调员的四类典型任务：项目周状态报告、项目会议纪要与待办、项目风险台账、里程碑核对。所有方法以已获准的本地材料为起点，不依赖项目管理工具或即时通讯的实时连接；连接为可选项，接入后仍按同一规则处理。

## 一、共同原则

1. **计划与实际分列**：任何进度表述都要同时写出计划值与实际（或预计）值，偏差由两者相减得出，读者可复算。
2. **状态词有依据**：「按计划」「延期」「阻塞」等判断必须指向材料中的日期、状态字段或负责人明确表述。
3. **预计不是实际**：成员口头给出的预计完成日期记为「预计」，写出给出者与时间，不写进「实际」列。
4. **不改基线**：岗位不重排计划、不提出新目标日期、不调整范围或资源；发现需要变更时列入「需负责人决策」。
5. **对外承诺单独标注**：报告或纪要中凡涉及已告知客户、合作方或上级的日期与范围，标「待负责人确认后对外」。
6. **不做个人归因**：延期原因只取材料中的表述，不写成员个人责任或绩效评价。

## 二、周状态报告

结构：整体状态（三档 + 依据）→ 本周完成（含成果依据）→ 进行中（含计划完成）→ 里程碑状态 → 阻碍与风险 → 下周计划 → 需决策事项。

整体状态判定：
- **正常**：无延期里程碑、无开放高风险、无阻断项
- **关注**：有延期但材料中有恢复计划，或存在开放高风险
- **告警**：关键里程碑延期且无恢复计划，或阻断项无人负责
- 材料不足以判定时写「待确认」

报告首部写明：报告期间、信息截止时间、来源清单、未核实假设。读者为客户或外部干系人时，不纳入内部人事、成本明细与未确认的责任归因。

## 三、会议纪要与待办

纪要严格区分：原文决议、计划变更（里程碑/范围/资源，需确认后生效）、行动事项（负责人与截止日期只取原文，缺失留空）、上次待办闭环、缺席确认、风险与问题（未成决议）、讨论摘要。

发言人身份不确定时记「[发言人待确认]」。相对日期默认原样保留；换算时写出会议日期星期并逐个核对星期，对不上的只保留原文并列入待确认。

计划变更只在纪要中标出，不直接写入里程碑表或风险台账。

## 四、风险台账

风险 = 尚未发生的不确定事项；已经发生的转为问题，由负责人决定处理方式。

每条风险登记：描述、触发条件、影响对象（里程碑/交付物）、类别（进度/范围/资源/质量/外部依赖）、可能性 1–5、影响 1–5、评分（乘积）、级别（≥15 高、8–14 中、<8 低）、应对方式、应对建议、建议负责人（只填材料指定的）、状态、来源、最后更新。

项目有自己的容忍说明或评分规则时以项目规则为准，并在台账首部注明。

风险接受、关闭与等级下调须由负责人确认；更新台账时不删除既有条目，只改状态并记录变更前后值。

## 五、里程碑核对

核对顺序：建立基线表（只抄计划材料）→ 匹配实际进度（已达成 / 进行中 / 未开始 / 无记录，写出匹配依据）→ 计算偏差（实际或预计 − 计划，正为延期）→ 判定（按计划 / 轻微延期 / 延期 / 待确认）→ 追溯依赖（缓冲小于偏差则「可能连带延期」，写出计算）→ 归集原因（只取材料原文）→ 决策事项。

未提供容忍范围时任何正偏差记「延期」并注明；未提供工作日历时按自然日计算并注明；模糊日期（「Q3 末」「月底」）在首部写出换算依据。

自检：每个计划里程碑出现一次；每个偏差可由两个日期复算；每个判定有依据；无材料之外的日期。
