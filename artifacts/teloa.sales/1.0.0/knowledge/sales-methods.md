# 商务协作方法与来源索引

## 适用范围

本文档适用于四类典型任务：客户研究简报、方案书草案、客户会议纪要与跟进事项、报价核对。所有方法以本人提供的客户材料、产品事实库、价格表与会议记录为起点，不依赖 CRM 连接或实时检索；如授权检索，只查客户组织的公开信息。

## 一、共同边界

1. **岗位不定价、不承诺、不签署**：价格、折扣、交期、服务水平、合同条款在所有产出中留空或只做核对，裁定交负责人。
2. **每条事实标来源**：文件写「文件名 + 位置」，网页写「访问地址 + 检索日期」；负责人口头提供的信息标「负责人提供，未见书面来源」。事实与推断分开。
3. **客户口头表述不写成「已确认」**：写「客户口头表示同意，待书面确认」。
4. **个人信息最小化**：客户联系人只记姓名与职务；电话、邮箱不进入简报或纪要；不检索联系人的个人社交账号；不汇总建立联系人档案。
5. **只用产品事实库**：产品能力、参数与案例必须回溯到事实库位置；事实库没有的写「待确认能否满足」，不写「可定制实现」。

## 二、客户研究简报

研究目的先写成一句（为哪次拜访、弄清什么、用于决定什么）。背景事实、客户已表达的需求（原文引用）、推断的关注点（写明依据哪些事实）三区分开。有产品事实库时做「客户需求 → 我方能力（事实库位置）」对应表；无则该栏留空。待确认问题写成拜访时能直接问的句子并注明为什么问。同一信息多个来源不一致时并列不选边。

## 三、方案书草案

需求逐条编号复述，歧义单列。能力对应三档：有对应 / 部分对应 / 待确认能否满足。默认结构：需求理解 → 方案概述 → 能力对应与说明 → 实施与交付框架（时间占位）→ 案例（只用已授权引用的，写明授权范围）→ 商务条款（全部占位）→ 待确认事项。未说明时不写竞品对比、不写未发布功能。

## 四、客户会议纪要与跟进

分类为客户需求 / 客户异议或顾虑 / 我方承诺（含承诺人）/ 跟进事项 / 讨论摘要。涉及价格、折扣、交期、服务水平的承诺单独标「商务承诺，需负责人复核」。「我们看看」「应该可以」归讨论摘要，不算承诺。负责人与截止日期只取原文。相对日期换算：先写会议日期与星期，逐个换算并核对星期，对不上则只保留原文进待确认项。

## 五、报价核对

顺序：价格表对照（项目是否存在、单价、计价单位）→ 数量与折扣（数量依据、折扣是否在规则内）→ 合计与税（行小计、合计、税率、含税口径、币种）→ 缺失与覆盖（需求有报价无、报价有需求无、缺有效期/付款条件/交付范围）。差额 = 报价单值 − 价格表值，不四舍五入。价格表无此项标注即可，不估价、不用相近项替代。不给「建议价」，不判断差异是否「可接受」。
