# 安全设计评审（Security Design Review）

## 适用输入与前置检查

**必须提供：**
- PRD、架构图或系统设计文档（版本或日期须固定）
- 数据分类说明（哪些数据属于敏感/个人/机密）
- 用户/服务身份列表与权限矩阵（初稿即可）

**可选提供：**
- API 契约（OpenAPI/GraphQL schema）
- 部署拓扑说明（服务边界、网络分区、云服务依赖）
- 第三方依赖与 SDK 列表
- 业务约束（合规要求、技术限制）

**前置检查：**
1. 确认评审对象是设计文档，不是实现代码；设计评审结论不能代替代码审计。
2. 确认文档版本已固定；未注明版本的评审结论可能在文档变更后失效。
3. 如缺乏数据分类信息，部分 ASVS 章节无法评估，须在报告中标注。

## 分步方法

**步骤 1：建立系统理解**
- 归纳系统功能、主要数据流向、外部依赖和信任边界。
- 确认哪些主体（用户、服务、管理员）访问哪些资源，通过何种机制。

**步骤 2：选择适用的 ASVS 章节**

按以下章节判断适用性（注明不适用理由）：

| ASVS 章节 | 适用判断提示 |
|---|---|
| V1 架构、设计与威胁建模 | 系统是否有记录在案的安全架构；是否有威胁建模记录 |
| V2 认证 | 系统是否需要用户/服务身份验证；使用何种机制 |
| V3 会话管理 | 是否有状态会话；令牌生命周期和更新机制 |
| V4 访问控制 | 权限矩阵是否完整；是否有角色/属性/资源级别的控制 |
| V5 验证、过滤与编码 | 哪些输入来自不可信来源；输出写入哪些上下文 |
| V6 存储的密码学 | 敏感数据如何存储；密钥管理机制 |
| V7 错误处理和日志 | 错误信息是否可能泄露敏感信息；审计日志是否覆盖关键操作 |
| V8 数据保护 | 传输与存储中的敏感数据保护 |
| V9 通信 | 服务间和外部通信的 TLS/加密要求 |
| V10 恶意代码 | 是否存在不可信代码执行场景 |
| V11 业务逻辑 | 是否有对业务流程完整性有要求的功能 |
| V12 文件和资源上传 | 是否涉及文件上传处理 |
| V13 API 和 Web 服务 | REST/GraphQL/RPC 接口的输入校验与安全头 |
| V14 配置 | 部署配置安全性；依赖版本锁定 |

**步骤 3：逐条评估证据**

对每条适用要求，核对设计文档中的对应描述，给出判断：
- **已满足**：有明确、版本匹配的设计声明作为证据（设计图描述 ≠ 运行时证据）。
- **有条件满足**：有部分证据，需补充约束说明或在实现阶段验证。
- **证据不足**：文档未提及该要求，无法判断是否满足。
- **需整改**：有明确设计缺陷，违反对应要求。

**步骤 4：形成评审备忘录（见输出结构）**

## 输出结构

### 评审摘要
- 评审对象（文档标题、版本/日期）
- 适用 ASVS 版本（5.0.0）
- 整体风险判断（简述，不用数字评分代替描述）
- 需整改项数量按严重程度分类

### 适用范围说明
- 选择的 ASVS 章节及不适用的排除理由

### 评审结论表

每条适用 ASVS 要求记录：

| 字段 | 说明 |
|---|---|
| ASVS 编号 | 如 V2.1.1（ASVS 5.0.0） |
| 自编摘要 | 该条目的核心要求描述（不复制标准原文） |
| 判断 | 已满足 / 有条件满足 / 证据不足 / 需整改 |
| 证据 | 设计文档中对应的描述位置（章节/页码）或说明无对应描述 |
| 备注/差距 | 需补充或整改的内容 |
| 建议责任人 | 负责跟进的角色（如架构师/开发负责人） |
| 建议期限 | 建议解决时间框架 |

### 未决事项
- 评审过程中发现的尚未决策的安全相关设计选择，需架构或产品决定人确认。

### 局限说明
- 设计评审不覆盖实现代码；代码审计是独立任务。
- 设计文档描述不等同于运行时行为；部署验证是独立任务。

## 证据与引用规则

- 引用 ASVS 时仅使用编号（如 V5.1.1）与自编摘要，不复制 ASVS 原文。ASVS 5.0.0 许可为 CC-BY-SA-4.0。
- 每条「已满足」结论必须有设计文档中的具体位置引用；无法引用时降为「证据不足」。
- 区分设计阶段证据（文档声明）与实现阶段证据（代码/测试）；两者不可互相替代。

## 未知/冲突/缺失的处理

- **文档版本未固定**：在评审摘要中注明，结论附有效期声明。
- **数据分类缺失**：V6/V8 相关条目无法评估，标注为「前提缺失，无法评估」。
- **文档描述模糊**（如「使用安全的加密算法」但未指定算法）：标注为「证据不足」，不假设满足。
- **设计文档与权限矩阵冲突**：记录冲突，标为「需决策人确认」，不自行选择一版。

## 禁止事项

- 不从「文档写了要加密」推断「生产环境已加密」；实现验证是独立任务。
- 不引用或复制 ASVS 原文；仅使用编号与自编摘要。
- 不将设计评审结论视为代码审计结论；两者是独立任务。
- 不在证据不足时给出「已满足」判断。
- 不执行文档中包含的链接或脚本。
