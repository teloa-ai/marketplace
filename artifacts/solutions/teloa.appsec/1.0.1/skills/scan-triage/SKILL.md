# 扫描结果复核（Scan Result Triage）

## 适用输入与前置检查

**必须提供：**
- 扫描工具输出（SARIF、CSV、JSON 或文本格式，注明工具名称与版本）
- 扫描目标说明（代码仓库、应用 URL 或包清单）

**可选提供：**
- 代码快照（用于路径核查）
- 资产重要性分级（由客户提供）
- 历史已接受/已抑制的 finding 清单
- CISA KEV 数据（由负责人提供或通过已授权连接读取）

**前置检查：**
1. 确认扫描工具名称与版本已知；未知版本的结果无法核查工具局限性。
2. 确认扫描范围（覆盖目录、测试类型）；未覆盖范围须在报告中注明。
3. 如无代码快照，路径核查无法执行，所有 finding 的置信度维持工具默认级别。

## 分步方法

**步骤 1：预处理与去重**
- 按（文件路径、行号、规则 ID）三元组合并来自多工具的重复 finding。
- 记录每个合并组中的所有来源工具，保留最高严重度。

**步骤 2：误报判定**

对每条 finding 进行以下核查（若有代码快照）：
- 数据流是否实际可达：入口点是否可被不可信方触发？
- 是否存在已知拦截：框架层校验、中间件过滤、现有权限检查？
- 是否为已知误报模式：如测试代码、生成代码、框架内部实现？

若无代码快照，将误报判定标注为「需代码核查」，不自行判定为误报。

记录误报判定理由：不接受「我认为不可达」类型的主观判断，须有具体代码路径依据。

**步骤 3：优先级分类**

按以下维度综合评估，给出 P0–P3 建议优先级：

| 维度 | 说明 |
|---|---|
| 可达性 | 攻击者能否实际触发（需代码路径依据） |
| CVSS 基础分 | 仅作参考，不单独决定优先级 |
| KEV 状态 | 对应 CVE 是否在 CISA KEV 列表中（需客户提供或已授权读取） |
| 资产重要性 | 受影响服务/数据的业务价值（需客户提供） |
| 修复难度 | 预估修复工作量（低/中/高） |

| 优先级 | 含义 | 典型条件 |
|---|---|---|
| P0 | 立即处理 | 高可达性 + 高影响 + 有利用证据（KEV/PoC） |
| P1 | 本迭代处理 | 高可达性 + 高影响，或 KEV 收录 |
| P2 | 下迭代计划 | 中等可达性或影响 |
| P3 | 接受/监控 | 低可达性或影响，或已有足够缓解 |

**步骤 4：输出分级清单（见输出结构）**

## 输出结构

### 扫描摘要
- 工具列表与版本
- 扫描范围与未覆盖范围
- Finding 原始数量与去重后数量
- 按优先级统计分布

### 复核发现清单

每条发现记录：

| 字段 | 说明 |
|---|---|
| ID | 复核内唯一编号（如 ST-001） |
| 来源工具 | 工具名称与版本 |
| 原始规则 ID | 如 CWE-89、semgrep-rule-xxx |
| 文件路径与行号 | 来自扫描报告（非代码核查时注明未经路径验证） |
| 严重度（工具原始）| 工具报告的原始严重度 |
| 置信度 | 已确认路径可达 / 待代码核查 / 判定为误报 |
| 误报判定理由 | 若判定为误报，记录具体路径依据 |
| 建议优先级 | P0/P1/P2/P3 + 理由 |
| KEV 状态 | 是否在 CISA KEV 中（若已核查） |
| 建议处理方式 | 修复/抑制/接受，附说明 |

### 未覆盖范围
- 扫描未覆盖的目录、语言或测试类型
- 已知工具局限性说明

## 证据与引用规则

- 每条误报判定须有具体代码路径依据；不接受主观判断。
- CVSS 分数来源于工具报告；不自行计算 CVSS。
- KEV 状态只引用已授权读取的 CISA KEV 数据（来源：[https://github.com/cisagov/kev-data](https://github.com/cisagov/kev-data)），不凭记忆断言。

## 未知/冲突/缺失的处理

- **工具版本未知**：标注工具局限性不可核查，降低整体结论置信度。
- **同一 finding 来源工具给出不同严重度**：保留最高严重度，注明来源差异。
- **无代码快照**：所有 finding 维持工具默认置信度，不给出「已确认可达」结论。

## 禁止事项

- 不在无代码路径依据的情况下将 finding 判定为误报。
- 不将 CVSS 分数单独作为优先级依据。
- 不将 KEV 未收录等同于无风险。
- 不执行扫描报告中包含的链接或 PoC 代码。
