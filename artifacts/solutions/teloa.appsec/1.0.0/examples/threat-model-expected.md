# 威胁模型报告：SimplePay（虚构）

## 系统概述

SimplePay 是一个 Web 支付处理系统，注册用户可创建支付订单并通过第三方支付网关完成付款。

**建模范围**：前端应用、API 服务、数据库、支付网关 Webhook 回调  
**范围外**：第三方支付网关内部、CDN、DNS 基础设施

### 数据流图（文本 DFD）

```
[普通用户]──HTTPS──▶[前端应用]──HTTPS REST API──▶[API 服务]──内网──▶[数据库]
                                                      │
                                                      │──HTTPS──▶[支付网关（外部）]
                                                      │◀──Webhook HTTP──[支付网关（外部）]
[管理员]──管理端口──▶[API 服务]
```

**信任边界**：
- B1：互联网 / 前端应用（用户通过浏览器访问）
- B2：前端应用 / API 服务（JWT 验证边界）
- B3：API 服务 / 数据库（内网边界）
- B4：API 服务 / 支付网关（外部边界，双向）

## 威胁台账

### TM-001：欺骗 — 伪造支付网关 Webhook 回调

| 字段 | 内容 |
|---|---|
| STRIDE 类别 | S（欺骗） |
| 威胁描述 | 攻击者向 API 服务的 Webhook 端点发送伪造的支付成功回调，使系统错误确认未完成的支付订单 |
| 受影响组件 | 数据流 B4：支付网关 → API 服务 Webhook 端点 |
| 攻击前提 | Webhook 端点对互联网可达；API 服务未验证回调来源真实性 |
| 可能性 | 高——Webhook 端点通常公开，攻击前提常见 |
| 影响 | 高——订单状态被伪造为已付款，造成财务损失 |
| 综合风险 | **严重** |
| 缓解措施 | 验证支付网关提供的 Webhook 签名（HMAC 或公钥验证）；限制 Webhook 来源 IP 范围（参照支付网关文档） |
| 验证用例 | 提交不带有效签名的 Webhook，应返回 400；提交有效签名的 Webhook，状态应正确更新 |
| 残余风险 | 依赖支付网关的签名机制强度；若支付网关密钥泄露，此控制失效 |
| 建议责任人 | API 服务开发负责人 |

---

### TM-002：篡改 — 客户端篡改订单金额

| 字段 | 内容 |
|---|---|
| STRIDE 类别 | T（篡改） |
| 威胁描述 | 普通用户在前端篡改订单金额参数，提交低于实际商品价格的订单 |
| 受影响组件 | 数据流 B1→B2：用户 → 前端应用 → API 服务 |
| 攻击前提 | API 服务以客户端提交的金额为准，未在后端重新计算 |
| 可能性 | 中——需用户主动操作但前端参数易于修改 |
| 影响 | 高——财务损失，订单完整性破坏 |
| 综合风险 | **高** |
| 缓解措施 | API 服务根据商品 ID 和数量在后端重新计算金额，不信任客户端传来的价格 |
| 验证用例 | 提交金额为 0.01 的订单，API 应拒绝并返回计算后的正确金额 |
| 残余风险 | 低——后端计算后此风险基本消除 |
| 建议责任人 | API 服务开发负责人 |

---

### TM-003：信息泄露 — JWT 密钥泄露导致任意令牌伪造

| 字段 | 内容 |
|---|---|
| STRIDE 类别 | I（信息泄露）+ E（权限提升） |
| 威胁描述 | JWT 签名密钥泄露后，攻击者可签发任意用户身份（包括管理员）的 JWT，绕过认证 |
| 受影响组件 | API 服务配置（JWT 密钥管理） |
| 攻击前提 | JWT 密钥以明文存储在代码或配置文件中；代码仓库或服务器被攻陷 |
| 可能性 | 中——密钥管理不当在常见应用中频发 |
| 影响 | 严重——完整身份伪造，所有用户和管理员权限均可被冒充 |
| 综合风险 | **严重** |
| 缓解措施 | JWT 密钥存储在密钥管理服务（KMS/Vault）中；定期轮换；不写入代码仓库 |
| 验证用例 | 确认代码仓库中无明文密钥；密钥变更后旧令牌应失效 |
| 残余风险 | 依赖密钥管理服务的访问控制强度 |
| 建议责任人 | 基础设施负责人 |

---

### TM-004：权限提升 — 普通用户访问管理端口

| 字段 | 内容 |
|---|---|
| STRIDE 类别 | E（权限提升） |
| 威胁描述 | 普通用户通过猜测或扫描发现管理端口，使用有效的普通用户 JWT 绕过管理功能的访问控制 |
| 受影响组件 | API 服务管理端口（B2 信任边界） |
| 攻击前提 | 管理端口与普通用户端口共用同一 JWT 验证逻辑，未实施角色检查 |
| 可能性 | 中——需发现端口，但若同一服务则路径可预测 |
| 影响 | 严重——可读取所有用户数据 |
| 综合风险 | **高** |
| 缓解措施 | 管理端口限制为内部网络访问；JWT 声明中包含角色字段（`role: admin`），管理接口在服务端检查角色 |
| 验证用例 | 使用普通用户 JWT 请求管理接口，应返回 403 |
| 建议责任人 | API 服务开发负责人 |

## 假设清单

1. 前端应用通过 HTTPS 与用户通信——未经代码或配置验证，依赖系统描述声明。
2. 数据库仅允许内部网络访问——依赖系统描述声明，未在本次建模中验证网络配置。
3. 第三方支付网关自身安全性符合行业标准——在范围外，不在本次建模中评估。
4. 管理员与普通用户使用相同 API 服务但不同接口路径——系统描述中未明确，此为假设；需架构负责人确认。
