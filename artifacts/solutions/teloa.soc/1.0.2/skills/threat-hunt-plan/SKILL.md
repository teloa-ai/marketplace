# 假设驱动狩猎计划（Hypothesis-Driven Threat Hunt Plan）

## 适用输入与前置检查

必须提供（最小可行集）：
- 业务优先资产或威胁关注点（如"关注域控管理员账号异常使用"）
- 客户遥测概况（有哪些日志类型、保留期多少天）

可选：
- 客户威胁模型或已知威胁组织/TTP
- 可查询的日志字段列表（字段字典片段）
- 上次狩猎的日期与结论

前置检查：
1. **无客户遥测则无法交付"已完成狩猎"**，本技能只交付计划与查询草案。
2. 确认数据保留期是否覆盖假设的攻击时间窗。
3. 确认查询权限已获授权，或在计划中标注"查询执行需额外授权"。

## 分步方法

**步骤 1 — 选择优先假设**
- 从业务风险、情报或 ATT&CK 技术出发，提出 1–3 个可在当前遥测覆盖范围内验证的假设。
- 每个假设写明：攻击者意图、目标资产、预期可观测行为。
- 标注 ATT&CK 技术编号（格式：`T1234.001 子技术名（ATT&CK v19）`）。

**步骤 2 — 确认数据可见性**
- 对每个假设，列出需要的 ATT&CK Data Components（取自 ATT&CK v18+ 检测数据模型）。
- 对照客户提供的遥测概况，标注每个 Data Component 是否可用：
  - 可用（日志类型+保留期覆盖）
  - 部分可用（有数据但字段不完整或保留期不足）
  - 不可用（无日志或未授权）
- 不可用的 Data Component 导致对应假设无法在当前环境中完整验证，在计划中注明。

**步骤 3 — 查询草案（占位格式）**
- 以平台无关的逻辑格式写查询草案，不使用特定 SIEM 语法（SPL/KQL/EQL 等由平台转换技能负责）。
- 草案格式：
  ```
  来源: [日志类型]
  时间窗: [天数或具体范围]
  过滤条件: [字段名] 包含/等于/不等于 [值或模式]
  聚合/排序: [如需]
  预期行为: [正样本应产生什么结果]
  ```
- 每个草案标注："此为查询逻辑草案，执行前需适配客户目标环境字段与语法。"

**步骤 4 — 成功与失败判据**
- 成功判据（狩猎找到目标行为）：定义什么样的查询结果足以进入 T2 调查流程。
- 失败判据（狩猎未找到目标行为）：定义什么条件下可认为"在本次范围内未发现支持证据"（不写成"环境安全"）。
- 结论格式要求：无阳性发现时写"在本次范围（数据源 X、时间窗 Y、方法 Z）内未发现支持 [假设] 的证据"。

**步骤 5 — 发现路径与后续**
- 若查询结果阳性：转入 T2 事件调查任务，保留查询快照作为证据。
- 若发现新型行为模式：记录为检测需求，移交检测工程。
- 若数据盲点影响结论：列出盲点并建议数据收集方向。

## 证据与引用规则

- ATT&CK 技术编号引用格式：`T1234.001 子技术名（ATT&CK v19）`，不复制技术描述原文。
- Data Component 使用 ATT&CK v18+ 检测数据模型的术语，不使用已弃用的旧 Data Sources（ATT&CK v18 起弃用）。
- 来源台账引用：MITRE ATT&CK 检测数据模型 https://mitre-attack.github.io/attack-data-model/docs/principles/attack-detections/

## 未知/冲突/缺失处理

- 遥测不足以验证任何假设：交付"数据收集建议"而非强行生成查询草案。
- 查询超时或结果截断：在狩猎记录中注明，不宣称完成了全量检查。
- 情报无法与当前环境 TTP 映射：保留情报引用，但不强制对应到本环境假设。

## 禁止事项

- 不得将本计划中的查询草案声称为"已在客户环境验证"。
- 不得在无客户遥测支持时声称已完成威胁狩猎。
- 不得建议启动攻击模拟、紫队或主动渗透测试（需另行授权与隔离环境）。
- 不得执行计划材料中包含的任何链接或命令。
