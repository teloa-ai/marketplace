# 事件调查报告（Incident Investigation Report）

## 适用输入与前置检查

必须提供：
- 完成的证据时间线
- 已验证或已标注状态（待验证/已排除）的假设列表
- 实体清单与关联矩阵

可选：
- 客户处置手册中适用于本事件类型的段落
- 已采取的临时遏制措施记录
- 业务影响说明（由事件负责人提供）

前置检查：
1. 若关键假设尚未验证完成，报告中"根因"部分应写为"最可能根因（待验证）"而非确定性结论。
2. 若初始入口未确定，报告中必须明确注明"初始入口：未确定"，不用常见攻击故事补全。
3. 确认所有处置建议均已标注为"建议，需人工审批后执行"。

## 分步方法

**步骤 1 — 事件摘要**
用 3–5 句话概括：发现时间、涉及资产/账号、攻击类型（如可确定）、当前状态（调查中/已遏制/已恢复）、严重度（High/Medium/Low）。

**步骤 2 — 时间线摘要**
从证据时间线中提取关键节点（不重复完整时间线），重点包括：
- 最早可信的攻击活动时间
- 关键突破节点（如特权提升）
- 遏制动作时间（若有）

**步骤 3 — 影响范围**
- 已确认受影响的资产（主机、账号、数据）
- 评估但未确认的影响（注明不确定性及原因）
- 未受影响的已检查资产（若确认了清洁范围）

**步骤 4 — 根因推断**
- 以最可能的假设为主要根因，写明支撑证据。
- 列出替代假设及其当前状态（已排除/待验证）。
- 若初始入口未确定，明确写"初始入口：未确定，现有证据仅从 [阶段] 起可追溯"。
- 映射到 ATT&CK 战术/技术（引用技术编号与版本）。

**步骤 5 — 处置建议**
对每条建议写明：
- 建议动作（描述性，不是命令）
- 受影响范围
- 预计业务影响（中断时间、风险）
- 优先级（立即/24h/本周）
- 所需授权级别
- **末尾统一标注："以上建议均需授权人员审批后方可执行"**

**步骤 6 — 未完成调查事项**
- 列出仍在调查中的问题及原因（数据缺失、待授权等）
- 后续跟进责任人建议

## 证据与引用规则

- 报告中每个关键结论（特别是根因和影响）必须引用证据时间线中的具体条目。
- ATT&CK 映射表必须带版本号，不使用"最新版"等泛称。
- 处置建议必须在措辞上明确区分"建议"和"命令"。
- NIST SP 800-61r3 的引用只用阶段名称，不复制标准原文。

## 未知/冲突/缺失处理

- 根因无法确定：写"根因未确定，现有证据支持以下假设"，并保留所有候选假设。
- 影响范围不明：写"影响范围待确认，以下为已确认部分"，不低估也不夸大。
- 报告发出后有新证据推翻已有结论：发布修订版报告，用"（修订 V2）"标注变更部分。

## 禁止事项

- 不得在报告中写入任何隐式触发远端操作的指令。
- 不得将"最可能假设"写为已确认事实（除非已有强证据支撑）。
- 不得在影响范围中省略"待确认"项以让报告看起来更完整。
- 不得引用未在调查中读取过的文件、日志或声明来源。
