# 交班记录（Shift Handover Record）

## 适用输入与前置检查

必须提供：
- 本班处理的告警/事件 ID 列表及当前状态
- 本班执行的关键动作（查询、升级、建议等）

可选：
- 未完成的调查事项说明
- 接班人员身份（用于记录）

前置检查：
1. 确认每个活跃事件的最新状态已更新。
2. 确认没有挂起的生产处置动作（若有，明确标注"待审批"状态）。

## 分步方法

**步骤 1 — 活跃事件清单**
- 列出本班所有告警/事件 ID、分类状态、处置状态、当前负责人。
- 对每个事件，用一句话说明"下一步最重要的事是什么"。

**步骤 2 — 本班动作记录**
- 只列关键动作（不是所有查询），特别是：升级、提交建议、暂停的调查、待批准的处置。

**步骤 3 — 关注点与警示**
- 下班后可能发生变化的风险点（如告警频率上升的主机、临近到期的证据保留期）。
- 数据盲点（某数据源不可用或查询被限流）。

**步骤 4 — 工具与连接状态**
- 记录本班发现的工具或连接异常（如 SIEM 查询超时、EDR 脱机主机数量异常）。

## 输出结构

```
# 交班记录

**班次时间**: [UTC 开始时间] — [UTC 结束时间]
**值班人员**: [当前任务执行者标识]
**接班人员**: [接班人 或 "待分配"]

---

## 活跃事件状态
| 事件/告警 ID | 分类 | 处置状态 | 下一步 | 负责人 |
|---|---|---|---|---|

## 本班关键动作
| 时间（UTC） | 动作描述 | 结果 |
|---|---|---|

## 关注点与警示
- [描述]

## 工具与连接状态
- [工具名]: [状态描述]

## 挂起的待审批动作
- [事件 ID] — [建议动作] — 等待: [审批人/授权说明]
```

## 证据与引用规则

- 每个活跃事件引用事件 ID，不凭记忆描述。
- 挂起的待审批动作必须明确列出，不隐含在"下一步"中。

## 未知/冲突/缺失处理

- 若某事件状态无法确认：写"状态不明，需接班人员优先核查"。
- 若数据源在班内恢复：记录中断时段，以便接班人评估期间证据缺口。

## 禁止事项

- 不得在交班记录中执行任何处置动作。
- 不得省略挂起的待审批事项（可能导致接班人重复提交）。
- 不得在交班记录中写入凭据或外部系统账号。
