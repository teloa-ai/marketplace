# 变更与回滚说明（Change and Rollback Notes）

## 适用输入与前置检查

必须提供：
- 变更后的规则（当前版本）
- 变更前的规则或描述（前一版本，用于说明变更内容）
- 样本回放报告摘要（测试覆盖状态）

可选：
- 规则库/SIEM 中的当前规则版本号（用于确认回滚目标）
- 计划的变更时间窗（由客户填写）

前置检查：
1. 变更说明必须如实反映测试覆盖状态，不得写"测试通过"而不列出测试范围。
2. 回滚版本必须是明确可识别的已知版本，不写"回到之前的版本"等模糊描述。

## 分步方法

**步骤 1 — 变更摘要**
- 规则 title 与 id
- 变更类型：新增规则 / 修改检测条件 / 添加过滤 / 修改日志源 / 调整严重度 / 废弃规则
- 变更原因：修复漏报 / 减少误报 / 更新 ATT&CK 映射 / 日志源变更 / 其他
- 变更内容摘要（具体修改了哪个字段或条件）

**步骤 2 — 版本信息**
- 当前版本：规则 `rev` 号（Sigma）或 `date` 变更
- 回滚目标版本：规则 `rev` 号（Sigma）
- 规则库中的引用 ID（若规则已在规则库中登记）

**步骤 3 — 影响范围**
- 覆盖的 ATT&CK 技术（变更前/变更后）
- 预计告警量变化：增加 / 减少 / 无显著变化（注明评估依据）
- 受影响的下游系统（SOAR、工单系统、通知规则等，若已知）

**步骤 4 — 测试覆盖状态**
- 正样本：已覆盖数量 / 命中符合预期数量
- 负样本：已覆盖数量 / 未误报数量
- 边界样本：已覆盖 / 未覆盖
- 未测试范围：明确列出（如未经过 X 平台测试）
- 测试环境：说明（如"仅在合成样本上手动验证，未在生产 SIEM 中执行"）

**步骤 5 — 回滚步骤**
写出具体的回滚操作步骤：
1. 确认回滚目标版本（Sigma rev 号 / 规则库 commit）
2. 在规则库中还原或重新加载旧版规则
3. 在目标平台中删除新规则并加载旧规则（客户参照平台操作手册执行）
4. 确认旧版告警已恢复运行（测试一条预期命中样本）
5. 记录回滚时间与执行人

**步骤 6 — 待客户填写的字段**
变更说明中预留以下字段供客户下发时填写：
- 计划变更时间窗：[___]
- 授权人员：[___]
- 变更工单 / 变更管理 ID：[___]
- 实际下发时间：[___]

## 证据与引用规则

- 测试覆盖状态引用样本回放报告中的样本 ID，不使用泛称。
- 版本号引用 Sigma 源规则的 `rev` 字段，保持与规则文件一致。

## 未知/冲突/缺失处理

- 回滚版本不明确：标注"回滚版本待规则库管理员确认"，不猜测。
- 测试覆盖不完整：在覆盖状态中如实列出，不补写为"测试通过"。
- 下游影响未知：标注"下游配置待确认"。

## 禁止事项

- 不得在测试未完成时写"测试通过"或"规则已验证"。
- 不得在变更说明中执行规则下发动作（规则下发由独立授权流程执行）。
- 不得省略"待客户填写"字段（避免下发缺少必要授权信息）。
