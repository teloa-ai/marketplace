# 检测需求梳理（Detection Requirements Analysis）

## 适用输入与前置检查

必须提供（至少一项）：
- 威胁描述（攻击者行为、目标或观察到的 IOC）
- MITRE ATT&CK 技术编号（如 T1059.001）

可选：
- 客户日志字段字典（确认哪些 Data Component 可用）
- 已知误报场景（同类正常行为描述）
- 既有检测规则（用于缺口分析）

前置检查：
1. 确认 ATT&CK 版本（本技能使用 v19.x，使用时确认最新版本）。
2. 若字段字典未提供，在需求文档中标注"字段可用性待客户确认"。

## 分步方法

**步骤 1 — 明确威胁假设**
- 用一句话描述攻击者意图：[攻击者角色] 通过 [方法] 对 [目标资产] 实施 [目的]。
- 标注对应 ATT&CK 战术（Tactic）与技术（Technique），格式：`T1234.001 子技术名（ATT&CK v19）`。
- 说明攻击行为的可观测点（什么行为在哪个日志中会留下痕迹）。

**步骤 2 — 确定数据源与 Data Component**
- 列出检测该行为所需的 ATT&CK Data Components（使用 v18+ 检测数据模型术语，不使用旧 Data Sources）。
- 对每个 Data Component：
  - 说明对应的日志平台类型（端点 EDR、Windows Security Log、网络流量、DNS 等）
  - 若客户提供了字段字典，标注字段可用性（可用 / 部分可用 / 不可用）
  - 若未提供，标注"需客户确认"

**步骤 3 — 关键字段清单**
- 列出检测条件所需的具体字段：
  - 字段名（Sigma 逻辑名，如 `CommandLine`、`ParentImage`）
  - 含义说明
  - 示例值（如有提供）
  - 目标平台对应字段（若已知）

**步骤 4 — 误报来源分析**
- 列出与目标行为特征相似的正常活动：
  - 误报场景描述
  - 区分恶意与正常的关键差异（用于过滤条件设计）
  - 涉及的高误报用户/系统类型（如管理员、备份代理、测试环境）

**步骤 5 — 验收判据**
- 定义检测规则通过验收所需满足的条件：
  - 正样本命中率（建议：关键样本 100% 命中，全量正样本 ≥90%）
  - 误报样本命中率（验收目标由客户根据误关代价设定，本技能建议 ≤5%）
  - 必须覆盖的边界场景（如大小写混写、路径变体、编码变体）
  - 不接受的静默降级（如移除逻辑以通过测试）

## 输出结构

```

### 威胁假设
- ATT&CK 映射: T[编号] [技术名称]（ATT&CK v[版本]）
- 描述: [攻击者行为一句话描述]
- 可观测点: [行为在哪个日志/系统中产生什么可见记录]

### 数据源与 Data Component
| Data Component | 日志平台类型 | 字段可用性 | 备注 |
|---|---|---|---|

### 关键字段清单
| Sigma 字段名 | 含义 | 示例值 | 目标平台字段（若已知） |
|---|---|---|---|

### 误报来源
| 场景描述 | 关键区分特征 | 涉及账号/系统类型 |
|---|---|---|

### 验收判据
- 正样本命中率目标: [客户设定值，建议≥90%]
- 误报率目标: [客户设定值]
- 必须覆盖的边界场景:
  1. [场景描述]
- 禁止静默降级: [具体说明]
```

## 证据与引用规则

- ATT&CK 引用格式：`T1234.001 技术名称（ATT&CK v版本）`，不复制技术原文描述。
- Data Component 使用 ATT&CK v18+ 检测数据模型术语。

## 未知/冲突/缺失处理

- 字段字典未提供：标注"字段可用性待客户确认"，不猜测字段名。
- ATT&CK 技术无对应 Data Component：标注"暂无标准 Data Component 映射，建议根据日志类型自定义"。
- 误报场景不明确：列出推断的高误报风险，标注"推断——需客户确认"。

## 禁止事项

- 不得在字段字典未提供时假设字段存在。
- 不得使用已弃用的旧 Data Sources（ATT&CK v17 及以前）。
- 不得将验收判据阈值固定为通用值——必须由客户根据业务代价设定。
