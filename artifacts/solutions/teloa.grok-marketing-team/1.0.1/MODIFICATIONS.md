# Modifications

Derived work: Teloa adapted this package from [cobusgreyling/grok-bot-templates@4f3f28b4e657](https://github.com/cobusgreyling/grok-bot-templates/tree/4f3f28b4e6578cd227ff7f4b78ec91d15fd091b5) (MIT, Copyright (c) 2026 Cobus Greyling). Every change from the original files is listed here.

- Format: each original `template.yaml` / `PROFILE.md` was mapped to a `teloa.role/v1` `roles/<bot>.json` (job, title, tagline, why, soul, deliverable → duty; sources + no_data → dataScope; autonomy, approval_never, approval_ask, plugins → executionScope; first_task → triggers; working_style → autonomousActions; approval_ask → confirmationPoints; no_data + handoffs → escalationRules; deliverable + never → deliveryChecks). The originals are kept verbatim under `references/<bot>/` and linked to the employee.
- Team: `teams/marketing/team.yaml` is kept verbatim as `references/team.yaml`. The coordinator is declared through role-coordination from the lead to each member, without authority or execution grants; group kickoff and handoffs remain references. Lead `competitor-watch` is stated in that employee's duty and in README.md, kickoff and handoffs stay as text. The coordinator links are stored with the fixed package and mapped to real employee identities; kickoff and handoffs do not automatically run work.
- Routines: an original routine becomes an unscheduled `teloa.work-template/v1` under `routines/` linked by role-work; no plan is created and nothing runs on import. The original `routine.yaml` (when the repository has one) is kept verbatim.
- Plugins: only GitHub and Notion are declared as optional read-only connections through Teloa catalog connectors (teloa.mcp-github, teloa.mcp-notion-remote). This package does not declare tools for: Gmail, Google Docs, Slack; the owner provides material or connects and authorizes suitable apps separately.
- Teloa added an optional dashboard guide for a separately adopted official industry dashboard. It is not an upstream file and adding the team does not create business records.
- `/workspace/<bot>/` paths in the originals are left as written; in Teloa they mean the employee's working directory.
- Example first-run outputs (`examples/first-run.md`) are fictional samples from the original repository, kept verbatim as references; they are not records of real runs.
- Employee display names and resource labels are localized for Teloa; approved built-in employee avatar keys are added. Original PROFILE/template files remain references; adapted fixed working-method skills provide the execution rules described below.

- Fact-policy correction: the competitor-watch no-data rule is adapted consistently in role dataScope, escalationRules[0] and its working-method PROFILE section. An unavailable page/capture does not imply nonexistence, deletion, access denial or an HTTP status. Preserve the known unavailable state and unknown cause unless current material or a real response supplies the cause. Raw references remain unchanged.
- Versioned native names: all six bundled methods use grok-marketing-1-0-1-<original-id>. Resource IDs, role-skill links, catalog skill bindings and routine skill references use the same mapping. This avoids replacing installations with older parent trust; it grants no permissions and upgrades no prior installation. Other method instruction bodies remain unchanged.
- This version has not passed real-model content-quality verification. Generation and catalog validation do not establish factual correctness of an actual output.
