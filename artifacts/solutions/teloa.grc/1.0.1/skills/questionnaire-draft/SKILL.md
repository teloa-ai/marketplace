# 安全问卷代拟

## 概述

为已收到的安全问卷（含客户安全评估问卷、供应商尽调问卷、SOC 2 相关问卷等）起草回答草案。草案明确标注每道题的置信度和需人工确认项，严禁代替负责人做出肯定性声明或签署合规承诺。

## 重要说明

> 本技能仅起草草案，不替代人工审阅和授权确认。以下情况必须由负责人确认后方可填写：
> - 涉及承诺"已完全实施"某项控制
> - 涉及合同性声明或法律承诺
> - 涉及认证状态（如"已通过 ISO 27001 认证"）
> - 置信度为"低"或标注"需确认"的任何项目

## 前置条件

- 问卷文件（含所有题目）
- 已有的策略文件、控制清单或证据（用于支撑回答）
- 组织背景信息（规模、行业、适用框架）

## 问卷类型

| 类型 | 常见来源 | 特点 |
|---|---|---|
| 客户安全评估问卷 | 企业客户采购前评估 | 关注数据处理、访问控制、事件响应 |
| 供应商尽调问卷 | 采购部门评估供应商 | 关注供应商安全能力和合规状态 |
| CAIQ（云安全）| 云客户使用方 | 基于 CSA CCM 框架 |
| SIG 问卷 | 金融行业客户 | 标准化供应商信息征集 |
| 自定义问卷 | 各类机构 | 题目结构不固定 |

## 回答草案步骤

### 第一步：题目分类

对每道题按以下维度分类：
- **领域**：访问控制/数据安全/事件响应/漏洞管理/物理安全/供应链/合规状态等
- **回答类型**：是/否/描述性/文件提供
- **风险敞口**：若回答不准确可能造成的影响

### 第二步：检索支撑证据

在已提供的策略文件和控制清单中检索对应信息，为每道题找到支撑依据。

### 第三步：起草回答

按以下格式起草每道题的回答：

```
题目编号：Q-001
题目原文：贵公司是否实施了多因素认证（MFA）？
建议回答：是。贵公司在所有特权账号和远程访问场景中强制要求 MFA。内部系统访问采用 [系统名称，待确认]，外部 VPN 访问采用 [工具名称，待确认]。
支撑证据：访问控制策略第 3.2 节（已提供）
置信度：中
需确认项：请确认内部系统和 VPN 所使用的具体 MFA 工具名称，并确认是否覆盖所有特权账号。
```

### 置信度标注规则

| 置信度 | 标准 | 处理方式 |
|---|---|---|
| 高 | 有明确策略文件或配置证据直接支撑回答 | 可直接使用，仍需负责人审阅 |
| 中 | 有间接证据或历史实践，无最新文档 | 需负责人确认后使用 |
| 低 | 基于推断，无文档支撑 | 必须由负责人确认并提供证据后才可使用 |
| 需确认 | 回答内容有重大影响或题目有歧义 | 必须由授权人确认签字后才可使用 |

### 第四步：汇总需确认项

在草案末尾列出所有需人工确认的项目清单，方便负责人集中处理。

## 输出结构

### 问卷回答草案

**草案标注**（首行）：
> 草案，待审阅确认后方可提交。所有"需确认"项必须由授权人确认后才可使用，本草案不得直接提交给问卷发送方。

**问卷元信息**：
```
问卷来源：[发送方名称]
问卷版本/日期：[如有]
题目总数：X 道
草案完成日期：[日期]
置信度分布：高 X 道 / 中 X 道 / 低 X 道 / 需确认 X 道
```

**逐题回答**：
按题目编号逐题提供建议回答、支撑证据、置信度和需确认项。

**需确认清单**（汇总）：
| 题目编号 | 需确认内容 | 建议确认人 |
|---|---|---|

## 常见题目类型回答框架

### 认证状态类

```
题目：是否持有 [认证名称]？
回答框架：
  - 如已认证：是，已通过 [认证机构名称] [认证名称] 认证，认证有效期至 [日期]。可提供证书副本。（需确认，请提供证书信息）
  - 如未认证：否，目前尚未取得该认证。组织按照 [框架名称] 的最佳实践管理信息安全。（需确认）
```

### 控制实施类

```
题目：是否实施了 [控制名称]？
回答框架（高置信度）：是，[控制描述]。相关策略记录在 [策略文件名称] 第 [章节号] 节。
回答框架（中置信度）：是（待确认），据了解 [控制描述]，但需负责人确认当前状态和覆盖范围。
```

### 事件响应类

```
题目：是否有事件响应计划？多久演练一次？
回答框架：是，组织制定了信息安全事件响应程序（[文件名，如有提供]）。演练频率为每年一次（需确认：请核实最近一次演练日期）。
```

## 局限说明

- 回答草案基于已提供的材料，不得超出已知范围做出声明
- 不对组织合规状态做出最终判断
- 本技能不具备法律资质，合同性声明须由法务和授权人确认
- 草案提交前须由对组织实际控制状态了解的负责人逐题核实
