# 证据索引

## 概述

证据索引是将已收集的安全控制证据（策略文件、配置截图、培训记录、审计日志等）与合规框架控制编号系统性关联的清单。本技能用于建立新索引或更新已有索引。

## 前置条件

- 已提供的证据文件列表（文件名、版本、描述）
- 目标框架控制清单（至少一个框架）
- 证据有效期信息（如有）

## 证据分类

### 技术控制证据

| 类型 | 示例 |
|---|---|
| 配置截图 | 防火墙规则、IAM 权限设置、MFA 配置 |
| 工具报告 | 漏洞扫描报告、SAST 扫描结果 |
| 系统日志 | 访问日志、变更记录（已脱敏）|
| 架构图 | 网络拓扑、系统组件关系 |

### 管理控制证据

| 类型 | 示例 |
|---|---|
| 策略文件 | 信息安全策略、访问控制策略 |
| 程序文件 | 变更管理流程、事件响应程序 |
| 培训记录 | 年度安全培训完成情况 |
| 审批记录 | 例外批准邮件、风险接受记录 |
| 合同文件 | 供应商安全协议、NDA |

### 证据有效期判断

| 证据类型 | 典型有效期 |
|---|---|
| 配置截图 | 3–6 个月（配置可能变更）|
| 策略文件 | 1 年（须年度审查）|
| 培训记录 | 1 年（须年度培训）|
| 渗透测试报告 | 1 年 |
| 审计日志 | 依法规要求，通常 1–3 年 |

## 索引建立步骤

### 第一步：证据清查

列出所有已提供的证据文件：
```
证据 ID：EV-001
文件名：information-security-policy-v2.pdf
描述：信息安全总策略，第 2 版
版本/日期：v2.0，2025-06-01
提供人/部门：信息安全部
有效期：2026-05-31
```

### 第二步：控制关联

对每项证据，映射到适用的框架控制编号：

```
证据 ID：EV-001（信息安全总策略 v2.0）
关联控制：
  - ISO 27001:2022 A.5.1（信息安全策略，自编摘要）
  - NIST CSF 2.0 GV.OC-01（自编摘要）
  - SOC 2 CC1.1（自编摘要）
  - 等保 2.0 8.1.2.1（自编摘要）
```

### 第三步：覆盖率分析

统计每个框架控制的证据覆盖情况：
- 有充分证据（1+ 项有效期内证据覆盖）
- 有部分证据（证据过期或覆盖不完整）
- 无证据（无任何相关证据）

### 第四步：缺口识别

识别没有证据覆盖的控制编号，列入差距分析清单：
```
无证据控制列表：
- ISO 27001:2022 A.8.8（技术漏洞管理）：无漏洞扫描报告
- ISO 27001:2022 A.6.3（安全意识培训）：培训记录缺失
```

## 输出：证据索引表

| 证据 ID | 文件名/描述 | 版本/日期 | 有效期 | 框架-控制编号 | 覆盖状态 | 备注 |
|---|---|---|---|---|---|---|

每行记录一项证据与一个控制编号的关联（一项证据可有多行）。

## 输出：证据覆盖汇总

```
证据总数：X 项（有效：X 项，已过期：X 项）
覆盖框架控制总数：X 项
  有充分证据：X 项（Y%）
  有部分证据：X 项（Y%）
  无证据：X 项（Y%）
```

## 更新机制

当以下情况发生时，需更新证据索引：
- 新审计周期开始
- 新系统或服务纳入合规范围
- 控制实施变更
- 证据到期（提前 30 天预警）

## 草案标注

证据索引首行必须注明：
> 草案，待审阅确认后方可使用。证据有效性和控制映射关系需由负责人核实。

## 局限说明

- 本索引基于已提供的文件列表，不对未提供文件的存在性做判断
- 证据有效性的最终判断需由负责人核实
- 证据内容的准确性依赖提供方，本技能不核实文件内容真实性
- 不包含对证据文件的内容安全评估
