# 例外到期复核

## 概述

安全例外（Security Exception）是组织对某项安全控制要求的临时豁免。本技能对到期或即将到期的例外申请进行复核，评估是否应延续、关闭或升级处理，输出复核报告草案。

**重要**：延续例外申请须由原授权人或更高级别授权人批准，本技能仅提供复核报告草案和建议，不自行延续或关闭例外。

## 前置条件

- 原例外申请记录（含批准日期、批准人、原始理由、到期日期）
- 当前控制状态信息（是否有进展或变更）
- 相关风险台账条目（如有）

## 例外生命周期

```
申请 → 风险评估 → 批准/拒绝 → 有效期内 → [到期提醒 30 天前]
                                              ↓
                                         复核评估
                                         ↙    ↓    ↘
                                      延续  关闭  升级
```

## 复核评估步骤

### 第一步：原例外背景还原

记录原始信息：
```
例外 ID：EXC-001
例外名称：[描述性名称]
适用控制：[框架控制编号和摘要]
批准日期：[日期]
原批准人：[姓名/职位，若已提供]
原到期日：[日期]
原批准理由：[摘要]
补偿控制（如有）：[描述]
```

### 第二步：当前状态评估

评估以下维度：

**1. 原批准理由是否仍有效？**
- 是否存在技术障碍（已知的，是否已解决？）
- 是否存在业务原因（是否仍适用？）
- 是否依赖第三方时间表（进展如何？）

**2. 补偿控制是否仍有效？**
- 补偿控制是否仍在运行？
- 补偿控制的效果是否经过验证？

**3. 风险变化评估**
- 威胁环境是否有变化？（如 CISA KEV 中是否有相关 CVE 被添加）
- 资产重要性是否有变化？
- 残余风险是否仍在可接受范围内？

**4. 整改进展评估**
- 批准时承诺的整改措施是否有进展？
- 是否设定了明确的整改里程碑？

### 第三步：建议生成

根据评估结果生成以下三种建议之一：

**建议延续**（满足所有以下条件）：
- 原批准理由仍然有效
- 补偿控制仍在有效运行
- 整改有实质性进展，有可信的完成时间表
- 残余风险仍在可接受范围内

**建议关闭**（满足以下任一条件）：
- 整改已完成，控制已实施
- 系统/业务已下线，例外不再必要
- 风险已转移（如通过保险或合同）

**建议升级**（满足以下任一条件）：
- 原批准理由已不成立，但整改仍未完成
- 风险水平显著上升（如相关 CVE 已被积极利用）
- 补偿控制已失效
- 例外已超过原定到期日且无进展

### 第四步：延续条件建议（仅延续场景）

如建议延续，提供：
- 建议延续期限（通常不超过原批准期限，一般 3–6 个月）
- 新的里程碑要求（整改进展节点）
- 需要更新的补偿控制（如有）
- 建议授权人层级（风险升高时需更高级别授权）

## 输出结构

### 复核报告草案

```
草案，待审阅确认后方可使用。例外延续须由授权人正式批准。

例外复核报告
例外 ID：EXC-001
复核日期：[日期]
到期日期：[日期]（[X] 天后到期 / 已逾期 [X] 天）

原例外摘要：
  [原批准理由摘要]

当前状态评估：
  原批准理由有效性：[有效/部分有效/已失效]
  补偿控制状态：[有效/部分有效/已失效/无]
  整改进展：[有进展/停滞/已完成]
  风险变化：[未变/降低/升高]
  综合评估：[说明]

建议：[延续/关闭/升级]
建议理由：[详细说明]

如建议延续：
  建议延续期限：[X 个月]
  新里程碑要求：[具体进展要求]
  建议授权层级：[职位级别]
  
需确认项：
  - [需要授权人确认的具体问题]
```

## 多例外批量复核

当有多个例外同时到期时，按以下顺序处理：
1. 首先处理建议升级的例外（最高优先）
2. 其次处理残余风险为高的延续类例外
3. 最后处理建议关闭的例外（最低风险）

批量复核时输出：
- 各例外复核报告草案
- 汇总表（例外 ID、到期日、建议、残余风险级别、建议授权人）

## 草案标注

每份复核报告首行必须注明：
> 草案，待审阅确认后方可使用。例外延续须由授权人正式批准，不得以本草案替代正式审批记录。

## 局限说明

- 复核基于已提供的例外申请记录和当前状态信息
- 威胁环境评估基于公开信息（如 CISA KEV），不代表完整威胁情报
- 补偿控制的有效性需由技术团队独立验证
- 不具备正式批准例外的权限
