# GRC 合规方案 (GRC Compliance Solution)

面向 GRC 团队的控制映射、证据索引、差距分析与整改计划、风险台账、安全问卷代拟和例外到期复核方案。

A solution for GRC teams covering control mapping, evidence indexing, gap analysis and remediation planning, risk register, security questionnaire drafting, and exception expiry review.

---

## 现在可做（What you can do now）

上传策略文件、控制清单或问卷后即可开始以下任务，无需任何在线连接：

- **控制映射**：将已提供的策略文件和证据，按 ISO 27001:2022、NIST CSF 2.0、SOC 2 TSC 或等保 2.0 逐条对照，输出带满足状态和缺口说明的映射表草案。
- **证据索引**：建立或更新证据文件与框架控制编号的关联索引，支持审计准备和持续合规管理。
- **差距分析**：基于映射结果，识别未满足和部分满足的控制，按残余风险优先级排序，为每条差距提供具体整改措施建议和整改计划草案。
- **风险台账**：将差距或已知风险登记为结构化风险台账条目，按 5×5 矩阵进行固有与残余评分，输出处理建议草案。
- **安全问卷代拟**：对已收到的安全问卷逐题起草回答，标注置信度和需人工确认项，形成可提交给授权人审阅的草案。
- **例外到期复核**：对即将到期的安全例外进行多维评估，输出延续/关闭/升级建议报告草案。

---

## 还需你提供（What you need to provide）

- **控制映射**：目标框架版本、已有策略文件或控制清单、业务范围说明。
- **证据索引**：证据文件清单（文件名、版本、日期）、目标框架控制清单。
- **差距分析**：已完成的控制映射表、业务背景说明、资产重要性信息（如有）。
- **风险台账**：风险来源材料（差距分析报告、事件记录或变更说明）、现有台账（如有）。
- **安全问卷代拟**：完整问卷文件、相关策略文件或控制清单、组织背景信息。
- **例外到期复核**：原例外申请记录（含批准日期和原始理由）、当前控制状态说明。

如需持续读取合规系统、证据仓库或风险台账平台，须另行配置对应连接。

---

## 会请求的权限（Permissions that may be requested）

- **只读**：读取你上传的策略文件、控制清单、证据材料和问卷（默认）。
- **可选**：合规管理平台或文档系统只读连接（用于持续维护控制映射和证据索引）。

以下权限**不在本方案范围内**，须独立授权后另行处理：
- 向审计机构或外部机构正式提交证据或合规声明
- 签署安全问卷或合规承诺书
- 批准例外申请或正式接受风险
- 修改策略文件或合规基线

---

## 已验证范围（Verified scope）

本方案仅交付可追溯的草案，基于已提供的静态材料。以下范围**尚未通过真实集成验收**：

- 与真实合规管理平台（如 ServiceNow GRC、Archer）的在线连接
- 直接从代码仓库或云平台拉取实时控制证据
- 自动化证据收集和持续合规监控

---

## 不包含（Not included）

- 替代负责人做出合规决策（所有决策性操作须授权人确认）
- 对外正式提交合规声明或问卷
- 批准风险接受或例外延续
- 出具正式审计意见或合规认证
- 替代客户自行判断适用的合规标准和版本
- 处理未提供的材料（如未提供策略文件，则不做推断）

---

## 合成示例

`examples/` 目录包含以下合成样例（均为虚构数据）：

- `control-mapping-input.md` + `control-mapping-expected.md`：虚构 SaaS 服务按 ISO 27001:2022 附件 A（10 项示例控制）的映射与差距分析报告。
- `questionnaire-input.md` + `questionnaire-expected.md`：虚构客户安全评估问卷（8 道题）及期望回答草案（含置信度标注和需确认项）。
